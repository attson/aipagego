# P4 连接器与安全分享验收记录（2026-10-27）

## 结论

- P4 的 8 条连接器、Job destination、安全包和远程边界场景均有可复现的自动化替代证据。
- 本轮 AIPageGo MCP `browser_start` 可以连接浏览器，但只返回普通网页标签，没有可操作的 extension sidepanel target；因此没有把普通网页、交互稿或组件测试宣称为扩展实机 smoke。
- 2026-10-23 的 P0 记录已经证明 production AppShell、原生 side panel、按需权限与危险审批能在独立 Chrome profile 中工作；该记录不替代本页的 P4 connector 实机验证。
- 本轮没有创建临时 Chrome profile、connector server 或外部系统 fixture，无此类资源需要清理。

## 8 条场景的替代证据

### 1. Webhook persistent connector

替代证据：

- `tests/background/connectors.test.ts` 覆盖 HTTPS/localhost 目标校验、secret 分区、write-only 摘要、synthetic test payload、cookie omit、redirect reject 和公开配置更新。
- `tests/background/delivery-service.test.ts` 覆盖固定发送 envelope、5 MiB 上限、source ref、计数和不保存 payload。
- `tests/sidepanel/drawers/connectors-drawer.test.tsx` 覆盖正式发送前的目标与数据规模确认，以及不回显 URL path/header value。

结论：行为和安全边界有自动化覆盖；没有声称真实外部 Webhook 已收到数据。

### 2. 飞书/Lark Base 501 行

替代证据：

- `tests/background/feishu-base-connector.test.ts` 覆盖 metadata test 不新增记录、token 只在内存使用、500 行 batch、501 行拆成两批及部分进度。
- `tests/background/delivery-service.test.ts` 覆盖 `sentCount` / `nextOffset`、失败分类，以及日志/错误不包含 secret、token 或 response body。

结论：批处理和敏感信息边界有自动化覆盖；没有调用真实飞书租户。

### 3. Session connector 重启失效

替代证据：

- `tests/background/connectors.test.ts` 覆盖 persistent/session 分区、session secret 缺失后 `needs_credentials`、重新写入后恢复，以及 secret 无 read-back API。
- `tests/background/jobs-service.test.ts` 与 `tests/background/jobs-safety.test.ts` 覆盖自动 Job 只能绑定 persistent + ready connector。

结论：浏览器重启后的 session storage 语义由存储隔离和缺凭据路径证明；未执行真实浏览器重启。

### 4. Job 成功、发送失败与仅重试发送

替代证据：

- `tests/background/jobs-service.test.ts`、`tests/background/jobs-runtime.test.ts` 覆盖工具成功后创建 delivery、delivery 失败时保留成功 output、Job 转为 `needs_attention`。
- `tests/background/delivery-service.test.ts` 覆盖 retry 复用 source ref，不重新运行 Tool/Job；`unknown_commit` 必须额外确认可能重复。
- `tests/sidepanel/drawers/jobs-drawer.test.tsx` 覆盖 delivery 独立状态与重试入口。

结论：Tool/Job 与 delivery 终态分离有端到端服务测试；未连接真实外部 endpoint。

### 5. Connector configHash 变化前置阻断

替代证据：

- `tests/background/connectors.test.ts` 覆盖公开配置或 secret revision 变化都会改变 `configHash`，hash 不包含 secret 明文。
- `tests/background/jobs-service.test.ts` 与 `tests/background/jobs-safety.test.ts` 覆盖在打开/操作页面前校验 connector、凭据和 hash；变化时进入 `connector_changed`，重新审核后才可恢复。

结论：阻断发生在页面副作用之前，有调用顺序断言；未在真实页面制造副作用。

### 6. active-only 安全分享包

替代证据：

- `tests/background/tool-share-export.test.ts` 覆盖 `aipagego.tool-package/v1` 只导出 active snapshot、重置 stats、去除 origin，并排除 Job、connector、credential、history、result 与 runtime 数据。
- `packages/shared/tests/tool-package.test.ts` 覆盖 canonical digest 与 secret scan；literal Authorization/API key 会拒绝，错误只含 rule/path，不回显值。
- `tests/sidepanel/drawers/tools-drawer-export.test.tsx` 覆盖多工具导出 UI 和安全错误显示。

结论：JSON 包内容和泄漏规则有结构化断言；未把测试包导入另一个真实 Chrome profile。

### 7. 两阶段安全导入

替代证据：

- `tests/background/tool-import-review.test.ts` 覆盖 v2、v3、package/v1，preview 只读，commit 重算 digest，unknown capability 拒绝，dangerous 未确认不落库，以及 copy/skip/overwrite。
- 同一测试覆盖 overwrite 的 tools + jobs 原子事务、依赖 Job warning/attention、并发默认 copy 和 digest TOCTOU。
- `tests/sidepanel/drawers/tool-packages-pane.test.tsx` 覆盖文件错误、逐项选择、dangerous 确认、部分拒绝、digest changed，以及提交成功后禁止重复提交。

结论：两阶段协议、存储原子性和 UI 门禁有自动化覆盖；未执行真实 sidepanel 文件选择器 smoke。

### 8. Coordinator/MCP 边界与既有能力

替代证据：

- `tests/background/coordinator-e2e.test.ts` 继续覆盖真实 `ws` server 下的 HELLO、EXEC 和 START_CHAT_SESSION。
- `tests/background/coordinator-exec.test.ts`、`tests/background/coordinator-chat-host.test.ts` 覆盖现有远程执行与 chat，不引入 connector 管理路径。
- `packages/mcp-server/tests/tool-gen.test.ts` 显式断言 full MCP 工具集合不包含 `connector`、`credential`、`delivery`、`webhook` 或 `feishu` 控制面入口。
- collection meta-tool、Coordinator/MCP handler 和协议测试继续覆盖 collection summary 与现有工具生成。

结论：远程能力无 connector CRUD/secret/send 扩面；既有 EXEC/chat/collection 路径由回归测试守护。
