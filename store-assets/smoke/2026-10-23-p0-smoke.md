1. Production AppShell 在全新 profile 中显示三步首次引导。
2. 用虚构 Key 和本机 mock endpoint 保存配置，最小连接测试成功。
3. 示例任务真实调用 `createPageIndex`；聊天显示“1 步成功执行”和最终五点页面总结。
4. `chrome.storage.local` 中 `firstRunDisposition = task_completed`，provider/model/endpoint 与输入一致；Key 仅按选择保存在 `chrome.storage.local`，未进入 IDB、导出包或日志。
5. 重新打开 AppShell 后不再显示首次引导。

首次三步链路使用 production AppShell 的非激活 extension tab，以保证被总结网页保持 active；随后点击工具栏扩展 action，Chrome 创建了独立的原生 side-panel target，后续权限和危险审批 smoke 均在该原生容器中完成。

### 按需权限

书签：

1. 进入 Bookmarks 分类前 `bookmarks=false`；只切分类不会请求权限。
2. 点击授权后出现 Chrome 原生权限框；拒绝后仍为 false，界面显示可重试。
3. 再次点击并允许后 `bookmarks=true`，书签入口进入结果态。
4. 设置页撤销后 `bookmarks=false`，已打开的 AppShell 立即清空缓存并重新显示授权入口。

历史：

1. 在原生 side panel 中调用 `searchHistory`，未授权时出现 AIPageGo 权限卡；此时 `history=false`。
2. 选择“暂不允许”后不读取历史，权限仍为 false；新会话可再次请求。
3. 重试并用可信点击选择“允许并继续”后出现 Chrome 原生 history 权限框；允许后 `history=true`，原 tool use 继续完成。
4. 设置页撤销后 `history=false`。

下载：

1. 在原生 side panel 中调用 `downloadSpreadsheet`，未授权时出现 AIPageGo 权限卡；拒绝后 `downloads=false`，没有创建文件。
2. 重试后出现 Chrome 原生 downloads 权限框；允许后 `downloads=true`，真实生成 `aipagego-smoke.xlsx`（2420 bytes）。
3. `file` 识别为 Microsoft Excel 2007+，`unzip -t` 检查全部 XLSX 条目通过；测试文件随后被精确删除。
4. 设置页撤销后 `downloads=false`。

最终复核：`bookmarks=false`、`history=false`、`downloads=false`。

### 危险审批独立性

在 `downloads=true` 时让 mock 模型调用 `submitForm({selector:"form"})`：

- side panel 仍显示 `dangerous / awaiting` 审批卡及“通过 / 跳过 / 终止”；Chrome capability 权限没有放行危险网页操作。
- 选择“跳过”后没有提交表单副作用，会话收到拒绝结果并正常结束。
- 这条链路与可选 Chrome 权限门禁相互独立。

### 实机发现并修复的问题

实机 smoke 发现：在设置页撤销书签权限后，已挂载的 AppShell 曾继续显示“已授权”和旧书签缓存。

修复后 AppShell 监听 `chrome.permissions.onRemoved`；当 bookmarks 被移除时立即清空缓存并恢复 `{state:"required"}`。`app-shell-bookmarks.test.tsx` 先红后绿，随后在真实 Chrome 中复测“允许 → 设置页撤销”，授权入口立即恢复。
